Requires 64-bit Windows 10 or later, with no additional runtime DLLs. The executable is now built with clang-cl instead of MSVC. Drop one or more `.bfsar` files onto `cafesf2.exe`, or use a terminal. `cafesf2 --help` lists the options. Output goes in a folder beside each archive.

For macOS on Apple Silicon, follow the build instructions in the README. Linux and Intel Macs are no longer supported. macOS builds include `Cafesf2.app`. Drop archives onto the app in Finder to convert them.

## New

- **`--voices N`** drops the notes that the game drops when every voice is in use, with N voices. nw::snd has 96 voices unless a game sets another count. Which notes the console drops isn't known exactly. The result only approximates the game. By default, cafesf2 keeps those notes.
- **Group files in SARC archives.** Some games keep the group files that they load in SARC archives, under other names. While a group is still missing, cafesf2 now reads the group files in the `.sarc` files beside the archive.

## Fixes

- **Vibrato that changes during a note.** A note whose pitch LFO changes while it sounds plays on a MIDI channel of its own. On that channel, pitch bends follow the game's LFO frame by frame, with its curve and phase. Such a note used to keep the LFO settings it started with. The change was only reported. Only a random curve is still reported there. Its random numbers can differ from those in the game. A volume or pan LFO that changes during a note is reported as before. So is a pitch LFO that changes when no MIDI channel is free.
- **Tempo at a loop's start.** A tempo change on the first tick of the main loop now comes after the loop markers (the `loopStart` marker and CC111). A player that loops resumes there. Each repeat therefore plays at the tempo of the loop's start. Playback without looping is unchanged.
- **Controller changes without notes.** A track's notes can spread over several MIDI channels, one for each set of settings. A set that plays no note now sends no controller changes. Its changes used to go to the track's first channel. A release could still be sounding there.
- **Tracks that wait for ever.** A track that waits a negative number of ticks now waits for ever. In the game, such a track never reads on. A sequence with such a track used to play on to the 15-minute limit. It now gets loop markers around another track's loop. When every track waits, it ends 10 seconds after its last change.
- **Counted loops.** A loop with a count that runs past the 15-minute limit becomes the main loop, with loop markers. The sequence used to be cut at the limit.
- **Fades in held sounds.** A sequence that holds until the game stops it ends 10 seconds after its last change. A ramp of the second volume or the main volume now counts as a change. A longer fade used to be cut short. The MIDI file now has the whole fade.
- **Many notes in one tick.** Without `--voices`, a track can start up to 1024 notes in one tick. cafesf2 used to keep the first 96. With `--voices`, the limit is the game's 96.
